# Прогноз недельных продаж с Apache Airflow и CatBoost

Учебный проект для сети дарксторов «Прилавок». Для планирования закупок модель оценивает продажи на неделю по каждой паре «даркстор — отдел». Airflow раз в неделю запускает пакетный расчёт по таблице плана и обновляет витрину прогнозов в PostgreSQL.

[Обучение и оценка в Jupyter](model_training.ipynb) · [DAG инференса](dags/batch_inference_dag.py) · [Подготовка признаков](dags/preprocessing.py)

## Модель и качество

Исходная история содержит 421 570 записей о продажах из 45 дарксторов. Для каждой пары «даркстор — отдел» из предыдущих наблюдений рассчитаны лаги на 1, 2 и 4 периода, скользящие средние и среднее по всей доступной истории. Дата, признаки праздника и характеристики даркстора дополняют историю продаж.

CatBoost обучен на 384 726 наблюдениях до сентября 2025 года. Временная валидация охватывает 23 710 наблюдений за сентябрь и октябрь. По индексу стабильности признаков (PSI) из модели исключены девять внешних показателей со значительным сдвигом распределения. Календарные признаки сохранены для учёта сезонности.

| Модель | Признаки | MAE, ₽ | RMSE, ₽ | R² |
|---|---:|---:|---:|---:|
| CatBoost на всех признаках | 23 | 1 465,25 | 3 049,07 | 0,98 |
| CatBoost после отбора по PSI | 14 | 1 458,63 | 3 053,28 | 0,98 |

В таблице приведены результаты сохранённого запуска ноутбука. Для инференса выбрана вторая модель. При валидации лаги учитывают фактические продажи прошлых недель, включая уже прошедшие недели валидационного периода. При расчёте плана на несколько недель вперёд DAG заполняет недоступные лаги нулями, поэтому качество на таком горизонте требует отдельной оценки.

## Как работает DAG

```text
load_data → preprocess_features ─┐
                               ├→ run_inference → save_predictions
load_model ────────────────────┘
```

1. `load_data` читает PostgreSQL, объединяет историю до первой даты плана с плановыми строками и сохраняет результат в промежуточную таблицу `inference_data_temp`.
2. `preprocess_features` готовит признаки, отбирает строки плана, заполняет недоступные исторические признаки и удаляет строки с оставшимися пропусками.
3. Параллельно `load_model` получает обученный CatBoost из S3-совместимого хранилища.
4. `run_inference` выбирает столбцы в порядке, записанном в модели, и строит прогноз. Отрицательные и неконечные предсказания заменяются нулями.
5. `save_predictions` пересоздаёт витрину `predictions` и записывает прогноз по ключу `(store, dept, date)` в одной транзакции.

Расписание DAG `sales_prediction_batch_inference` — воскресенье, 20:00 по часовому поясу DAG. В этой реализации задачи загрузки модели и инференса должны видеть один временный каталог. Подготовленные строки и прогнозы передаются через XCom в формате JSON.

## Данные и запуск

Для запуска нужна PostgreSQL со следующими исходными таблицами. Данные и обученный файл модели предоставляются пользователем или создаются в его окружении.

| Таблица | Поля |
|---|---|
| `sales` | `store`, `dept`, `date`, `weekly_sales`, `is_holiday` |
| `stores` | `store`, `type`, `size` |
| `features` | `store`, `dept`, `date`, `temperature`, `fuel_price`, `factor1`–`factor5`, `cpi`, `unemployment` |
| `plan` | `store`, `dept`, `date`, `is_holiday` |

Для обучения подготовьте окружение Python 3.10 или 3.11. Следующие команды рассчитаны на Linux или WSL, поскольку в общий список зависимостей входит Apache Airflow.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
jupyter lab model_training.ipynb
```

Заполните в `.env` параметры PostgreSQL из [.env.example](.env.example) и выполните ячейки по порядку. Ноутбук сохранит модель в `artifacts/catboost_model.pkl`. Чтобы также отправить модель в Yandex Object Storage, задайте `S3_ACCESS_KEY_ID`, `S3_SECRET_KEY`, `S3_BUCKET` и путь `S3_MODEL_KEY`.

Для пакетного запуска в Airflow 2.10.5 установите зависимости из [requirements.txt](requirements.txt), скопируйте оба файла из [dags/](dags/) в каталог DAG и настройте подключение:

- **PostgreSQL** — Connection `postgres_sales_db` с доступом к исходным таблицам и правами на создание, запись и удаление промежуточной таблицы и витрины.
- **Хранилище модели** — Variables `s3_access_key`, `s3_secret_key`, `s3_bucket_name` и `s3_model_key`. По умолчанию DAG использует Yandex Object Storage. Для другого S3-совместимого хранилища укажите `s3_endpoint_url` и разместите в нём модель.
- **Запуск** — включите `sales_prediction_batch_inference` и запустите DAG. Прогноз доступен в столбце `predictions.predicted_weekly_sales`.
